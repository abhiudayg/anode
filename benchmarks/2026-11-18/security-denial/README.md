# Security denial matrix, probe run (2026-11-18)

What was run: `probe.py` and `oom.py`, started under units generated by the real template (`deployer.GenerateSystemdUnit`, see `probe.unit` and `oom.unit`). The services run as a dynamic user (uid 64447 in the run).

Host: OrbStack Ubuntu 26.04 arm64 VM, systemd 259. This is a local VM, not a plain VPS. Its `/run/systemd/system/service.d/zzz-lxc-service.conf` drop-in overrides some directives, see below.

Not verified on this host:
- **ProcSubset / ProtectProc:** the unit has `ProtectProc=invisible` and `ProcSubset=pid`, but the drop-in sets `ProcSubset=all` and `ProtectProc=default`, and the probe found 52 non-PID entries in `/proc`. This is an environment override. A plain host has to be tested before the claim is made.
- **Exposure score:** computed with the same drop-in. Run it on a plain host.

Reproduce (on a Linux host with systemd, as root):
```
install -m 755 probe.py /opt/probe/probe.py && install -m 755 oom.py /opt/probe/oom.py
install -m 644 probe.unit /etc/systemd/system/anode-probe.service
install -m 644 oom.unit /etc/systemd/system/anode-probe-oom.service
systemctl daemon-reload && systemctl start anode-probe.service && sleep 4 && cat /var/lib/probe/results.json
systemctl start anode-probe-oom.service   # then check journalctl for the oom-kill and NRestarts
```
